All notable changes to `aloli-crystal/pdf2text` are documented

== v0.6.1 — 2026-06-06 — binary renamed `pdftohtml` → `pdf2html`

=== Changed

* **Binary renamed `pdftohtml` → `pdf2html`** (`src/bin/pdf2html.cr`,
  `pdf2html` shard target). Avoids the name clash with poppler-utils'
  own `pdftohtml` on `PATH` and aligns with the sibling `pdf2text`
  binary. The HTML engine (`Pdf2Text::Html`) and the CLI behaviour are
  unchanged.

== v0.6.0 — 2026-06-05 — `pdftohtml` : positioned HTML rendering

=== Added

* **`Pdf2Text::Html`** (`src/pdf2text/html.cr`) — renders an `Extract`
  to a self-contained HTML document, the equivalent of poppler's
  `pdftohtml` : one `<div>` per page sized to the MediaBox, one
  absolutely-positioned `<span>` per word (PDF bottom-left origin →
  HTML top-left), preserved font size and a font-family heuristic.
  Text is escaped (`HTML.escape`).
* **`pdftohtml` binary** (`src/bin/pdftohtml.cr`) — new shard target,
  ALOLI CLI conventions. `pdftohtml <doc.pdf> [<out.html>]` with
  `-o/-f/-l/-s(stdout)/-t(title)/-p`. Pure reading.

=== Fixed

* Stale notes corrected : the CLI and module doc still described text
  extraction as a "preliminary" sketch returning "0 words" for most
  PDFs. That has been false since v0.2.0+ — Type1/WinAnsi and CID
  Type0/Identity-H/ToUnicode extraction is reliable (verified : 8175
  words from a 21-page PDF). (The EN changelog also lacked the
  v0.2.0–v0.5.0 entries kept in CHANGELOG.fr.adoc.)
