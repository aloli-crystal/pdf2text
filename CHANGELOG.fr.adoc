== v0.5.0 — 2026-06-04

=== Corrigé / Ajouté

* **Largeurs EXACTES par CID brut (fin des mesures faussées sur
  certaines fontes).** La largeur d'un run de texte était calculée
  par `FontInfo#width_of`, qui décode le texte en Unicode puis
  re-mappe chaque caractère vers un CID via la table inverse de
  `ToUnicode`. Ce détour est *lossy* : plusieurs CID peuvent
  partager un même Unicode, et la valeur récupérée n'était pas
  toujours celle du glyphe réellement tracé. Conséquence : des
  mots mesurés jusqu'à ~25 % trop étroits, provoquant de faux
  `huge_gap` dans pdf-audit.
+
  Nouveau chemin : `decode_with_widths` décode la string PDF en
  renvoyant À LA FOIS le texte ET la largeur de CHAQUE caractère,
  mesurée directement depuis le CID brut du flux via
  `FontInfo#cid_width(cid)` (lookup `/W` sans détour Unicode). Les
  positions de mots correspondent désormais au pixel près à la
  référence poppler (`pdftotext -bbox`).

* **`split_into_words` : positions par vraie chasse de glyphe.**
  La méthode répartissait `largeur_totale / nb_caractères`
  uniformément — approximation grossière pour une fonte
  proportionnelle. Elle s'appuie maintenant sur le tableau de
  largeurs par caractère fourni par `decode_with_widths` : chaque
  mot avance le curseur de la somme exacte des chasses de ses
  glyphes.

* **Parse `/W` robuste (bug du préfixe de sous-ensemble en « W »).**
  `parse_cid_widths` localisait le tableau `/W` via
  `desc_s.index("/W")`. Quand le préfixe aléatoire de sous-ensemble
  de la fonte commençait par « W » (ex. `WSMHES+DejaVuSans-Bold`),
  ce `/W…` matchait le `/BaseFont` au lieu du tableau de largeurs ⇒
  `cid_widths` vide ⇒ largeurs estimées au lieu d'exactes. La
  recherche exige désormais que `/W` soit suivi (après espaces)
  d'un `[`, en itérant les occurrences pour ignorer `/WSMHES…`,
  `/WMode`, etc. (Cas vécu : la fonte grasse du README beryl FR.)

=== Impact

Sur les PDFs du README beryl (gén. crystal-asciidoctor-pdf), les
bbox des mots — y compris en gras et avec diacritiques (é, è) —
coïncident désormais avec poppler. Les faux positifs `huge_gap`
de pdf-audit dus à la sous-mesure du gras disparaissent.

== v0.4.0 — 2026-06-04

=== Ajouté

* **Fallback `effective_default_width` (médiane des widths).**
  Le `FontInfo#width_of` utilisait précédemment `default_width`
  (typiquement 1000 unités) comme largeur fallback pour les
  CIDs non listés dans `/W` — beaucoup trop large, car la
  médiane d'une fonte est typiquement ~500 unités (= un
  caractère « moyen » à 0,5 em). Conséquence : les chars rares
  (`→`, `…`, certaines ponctuations finales) étaient mesurés
  2× trop larges, faussant les bbox de pdf2text et créant des
  faux positifs `margin_overflow` côté pdf-audit.
+
  Nouvelle méthode `FontInfo#effective_default_width` qui
  calcule la médiane des `cid_widths` connus au premier appel
  (puis cache). Cette médiane remplace `default_width` comme
  fallback de `width_of`. On garde le `min(median, default_width)`
  pour rester conservateur dans les rares cas où la médiane
  serait plus large que le `/DW` déclaré.
+
  Impact : sur le PDF du README beryl, certains chars rares
  voient leur bbox.width réduite de ~50 %, ce qui rapproche
  les mesures pdf2text de la vérité visuelle du PDF.

=== À noter

Le nombre de mots extraits passe de 2681 à 2794 sur le beryl
PDF — légère augmentation due à un meilleur calage des positions
qui révèle quelques mots adjacents auparavant fusionnés.

== v0.3.0 — 2026-06-04

=== Ajouté

* **Bbox précises via parsing du tableau `/W` (CIDFont widths).**
  Le `FontInfo` stocke désormais :
+
  - `cid_widths : Hash(UInt16, Float64)` — largeur par CID en
    unités texte (1/1000 em), parsée depuis le `/W` du
    `DescendantFont` du Type0.
  - `default_width : Float64` — `/DW` (défaut 1000 = 0.5 em),
    fallback pour les CIDs absents de `cid_widths`.
+
  Le parser `/W` supporte les deux formats Adobe :
+
  0. `CID [w1 w2 w3 ...]` : assignation aux CIDs consécutifs
     depuis `CID`.
  0. `CID_first CID_last w` : assignation uniforme à toute la
     range.
+
  La largeur d'un texte est désormais calculée glyphe par glyphe
  via `FontInfo#width_of` : pour chaque caractère, on cherche son
  CID (via reverse-lookup du `cid_map`) puis sa largeur dans
  `cid_widths`. Plus de moyenne `avg_advance` approximative.
+
  Vérification sur le README beryl (DejaVu Sans Bold/Sans/SansMono) :
+
  [%autowidth]
  |===
  | Mot | pdf2text x | pdf2text w | pdftotext x | pdftotext w
  
  | `Beryl`    | 36.0  | **82.0** | 36.0  | **82.0** ← identique
  | `Table`    | 36.0  | 41.8     | 36.0  | 43.3 ← Δ 1.5 pt
  | `matières` | 119.7 | 67.0     | 116.9 | 69.7 ← Δ 2.8 pt
  |===
+
  Les bbox sont maintenant exploitables par les outils d'audit
  pour détecter :
+
  - mots débordant la marge droite (`x_max > target_x`)
  - mots collés (gap entre xmax du précédent et xmin du suivant
    inférieur à un seuil)
  - lignes très étalées (somme des gaps > seuil)
  - asymétries de marges
+
  Les différences résiduelles vs pdftotext (~1-3 pt par mot)
  viennent du fait que notre cursor avance caractère par caractère
  avec les widths /W, alors que pdftotext peut utiliser les
  bounding boxes glyphe-par-glyphe issues directement du programme
  de fonte TrueType. Suffisant pour l'audit visuel.

== v0.2.0 — 2026-06-04

=== Ajouté

* **Extraction texte fonctionnelle via ToUnicode CMap.** Le
  parser PDF natif décode désormais les fontes CIDFont Type0
  avec encoding Identity-H — soit la quasi-totalité des PDFs
  produits par `aloli-crystal/pdf`. Pour chaque font, on parse
  son dictionnaire `/ToUnicode`, on récupère le CMap stream
  (FlateDecode décompressé), et on construit une table CID
  16-bit → texte Unicode. Lors du parsing du content stream,
  les strings HEX `<002500480055>` sont décodées en CIDs puis
  mappées en Unicode.
+
  Test comparatif sur 5 PDFs de la baseline crystal-asciidoctor-pdf
  (beryl, crystal-combine-pdf, toml, noto-cjk, deploy) : `pdf2text`
  extrait systématiquement **plus de mots** que `pdftotext`
  (référence poppler) — +196, +460, +186, +89, +224 mots
  respectivement. La différence vient principalement du fait
  qu'on splitte la ponctuation collante alors que pdftotext la
  garde groupée — comportement préférable pour les outils
  d'audit qui veulent compter les tokens.

=== Corrigé

* **`decode_stream` bytes-safe pour la détection FlateDecode.**
  Avant : on convertissait l'object body en String UTF-8 et on
  cherchait `/FlateDecode` via `String#includes?`. Pour les
  objets avec dict contenant des bytes binaires (cas des fonts
  embarquées et des CMaps), la conversion perdait l'info et le
  marqueur n'était pas détecté → décompression skipée, contenu
  binaire renvoyé tel quel, parser CMap voit du noise. Le check
  est désormais fait sur les bytes bruts via `find_pattern`,
  avec en plus une détection par **signature zlib** (`78 01`,
  `78 9C`, `78 DA`) qui rattrape les cas où le filter n'est pas
  formaté `/FlateDecode` standard.
+
  Impact : sur le PDF beryl, le nombre de CIDs extraits par
  fonte passe de 0 (échec silencieux) à 61 (DejaVuSans-Bold) /
  84 (DejaVuSans) / 72 (DejaVuSansMono).

* **Nom de fonte propre.** Avant : le regex `/BaseFont \/(\S+)`
  capturait trop largement et le `font_name` retourné
  contenait `/Encoding` du champ suivant (ex.
  `QPQBSE+DejaVuSans-Bold/Encoding`). Le pattern devient
  `/([^\/\s>]+)/` — borné par `/`, espace, ou `>`. Résultat :
  `QPQBSE+DejaVuSans-Bold`.

* **`parse_to_unicode_cmap` tolère les bytes non-UTF8.**
  Filtrage des bytes non-printables vers espace avant le scan
  regex PCRE2 (qui rejette UTF-8 invalide). Aucune perte
  d'information utile : le contenu syntaxique du CMap est
  ASCII pur.

* **Tokenizer de TJ array gère les strings hex.** Avant : le
  parseur du tableau TJ ne reconnaissait que les strings
  parenthésées `(text)`. Pour les CIDFont qui émettent
  `[<00010002> -50 <00030004>]`, on perdait tout. Extension à
  `<hex>` en plus de `(text)`.

* **`decode_string` polymorphe.** Le décodeur de string PDF
  reconnaît désormais les deux formes (`(literal)` et `<hex>`)
  et reçoit la `FontInfo` courante pour appliquer le CID map
  approprié sur les strings hex.
